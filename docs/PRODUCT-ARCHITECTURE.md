# Семейная кухня — продуктовая архитектура (v1)

**Статус:** источник правды для реализации (HTML → при необходимости сервер)  
**Семья:** Данила + жена + дочка ~1,5 года  
**Контекст:** Богданиха (МО), магазины Ашан / Пятёрочка / Парное мясо (Молоково), отказ от ВкусВилл, полный бюджет еды+алко+вкусняшки 50–80к, готовка batch 2–7 дней  

Этот документ — не описание текущего прототипа, а **целевая архитектура продукта**, от которой строим прод.

---

## 1. Продуктовый тезис

> Приложение — это **операционная система домашней еды**: что есть → что готовим → что купить → как приготовить → что осталось → сколько потратили.  
> Оно снимает с семьи три боли сразу: **деньги**, **решение «что на ужин»**, **логистику готовки** — без превращения жизни в трекер-каторгу.

Не «каталог рецептов». Не «меню на холодильник».  
А **совместный семейный планировщик с умным подбором**, где муж и жена могут за 2–5 минут закрыть вопрос еды на дни вперёд.

### Анти-цели (чем продукт не является)

- Не соцсеть и не контент-медиа про еду
- Не жёсткий калорийный коуч / ЗОЖ-приложение (БЖУ — опционально позже)
- Не замена магазина и не маркетплейс
- Не «идеальная семья без отклонений»: алкоголь, вкусняшки и срывы плана — **нормальные сущности**, а не стыд

## 2. Персоны и роли

### 2.1. Данила — «Архитектор системы»

| | |
|--|--|
| **Мотив** | Экономия, контроль бюджета, системность, меньше хаоса |
| **Страх** | Снова >100к на еду; приложение, которым пользуется только он |
| **Поведение** | Любит настроить правила, прайс, закупку мяса крупно, смотреть цифры |
| **Критерий успеха** | Видит месячный прогноз ≤ целевой полосы; корзина собрана; план на неделю ясен |
| **Интерфейсный режим** | «Командный центр»: бюджет, закупка, запасы, аналитика, правила |

### 2.2. Жена — «Исполнитель и редактор вкуса»

| | |
|--|--|
| **Мотив** | Меньше думать «что готовить»; вкусно; реально успеть за ~час раз в 2 дня |
| **Страх** | Сложный интерфейс, «мужская табличка», рецепты на 40 шагов, чувство вины за вкусняшки |
| **Поведение** | Открывает телефон на кухне: что сегодня, как сделать, чего не хватает |
| **Критерий успеха** | Один экран «сегодня + завтра»; крупный текст; 3 кнопки; список шагов без воды |
| **Интерфейсный режим** | «Кухонный режим» / «Сегодня»: минимум настроек, максимум действия |

### 2.3. Дочка (косвенный пользователь)

Не пользуется UI, но **жёстко влияет на правила**: без сахара/мёда/орехов, соль умеренно, специи аккуратно, рыба без костей, можно отдельную ветку блюд. Приложение всегда показывает **детскую адаптацию** к выбранному блюду.

### 2.4. Ролевая модель в продукте

- **Владелец правил** (по умолчанию Данила): бюджет, магазины, запреты, стратегия мяса  
- **Соавтор меню** (оба): лайк/дизлайк блюд, замены, «не хочу это на этой неделе»  
- **Дежурный по кухне** (сменный): чекбокс «приготовил», остатки, фото «как вышло» (опционально)  
- **Закупщик** (сменный): корзина → чекпоинты магазина  

Смена ролей без смены аккаунта на старте: **переключатель профиля «Я / Жена / Кухня»** (локальные пресеты UI).

## 3. JTBD (Jobs To Be Done)

### Главные работы

1. **Когда** кончаются продукты / заканчивается неделя, **хочу** за 10 минут понять, что готовить и что докупить, **чтобы** не срываться в готовую еду и ВкусВилл.  
2. **Когда** открываю холодильник и вижу «остатки», **хочу** получить 3–7 вариантов блюд «из того что есть», **чтобы** не выкинуть еду и не ехать в магазин.  
3. **Когда** жена готовит раз в 2 дня ~час, **хочу** batch-план на 2–7 дней с понятными шагами, **чтобы** один подход закрывал несколько приёмов.  
4. **Когда** смотрю на траты, **хочу** видеть прогноз месяца (еда / алкоголь / вкусняшки отдельно), **чтобы** держаться 50–80к без ощущения «нас ограбили».  
5. **Когда** мы с женой вдвоём планируем, **хочу** общее меню без споров «ты опять курицу», **чтобы** разнообразие и мясо/рыба были закрыты автоматически.  
6. **Когда** готовлю для дочки, **хочу** сразу видеть, что убрать/заменить, **чтобы** не держать в голове отдельное меню каждый раз.

### Вторичные работы

7. Заморозить «удачный ужин» в избранное / шаблон недели.  
8. Съездить в Парное мясо раз в 2–4 недели с готовым списком кг.  
9. Вечером быстро ответить: «что на завтрак из готового?».  
10. Не сорвать план, если гости / болезнь / лень — мягкий режим замены на 1 клик.

## 4. Ценность, профиты, преимущества

### 4.1. Ценность для семьи (outcomes)

| Outcome | Как измеряем |
|---------|----------------|
| Снижение трат на еду с >100к к 50–80к | Факт vs план по месяцу |
| 0 покупок ВкусВилл / готовой еды «по привычке» | Счётчик «срывов» (честный, без морали) |
| Решение «что есть» < 3 мин | Время до сохранённого плана |
| Готовка укладывается в паттерн 1 ч / 2 дня | % дней, закрытых batch-остатками |
| Оба пользуются | DAU/WAU по профилям «Кухня» и «Командный» |
| Меньше выброшенного | % «спасённых» продуктов через подбор из запасов |

### 4.2. Преимущества vs альтернатив

| Альтернатива | Почему наш продукт лучше |
|--------------|---------------------------|
| ВкусВилл / готовое | Дешевле в 2–3+ раза при том же «не думать», но с контролем |
| Бумага / Excel | Умный подбор, корзина, детские правила, совместный UX |
| Книга рецептов / YouTube | Привязка к **вашим** запасам, ценам и магазинам рядом |
| Доставка еды | Batch + свой вкус + алкоголь/вкусняшки в одной картине бюджета |
| «Просто помнить» | Семья с ребёнком и усталостью — память не масштабируется |

### 4.3. Продуктовые «моменты магии»

1. Ввёл остатки за 90 секунд → получил ужин на сегодня и завтра.  
2. Выбрал 4 блюда на 3 дня × N порций → корзина с раскладкой по магазинам и «можно не покупать, уже есть».  
3. «Большой день готовки» → чеклист по таймингу (что ставится первым).  
4. Прогноз: «если так питаться месяц, базовая еда ≈ 31к».  
5. Режим жены: один экран, крупные кнопки «Готовлю это» / «Заменить».

## 5. CJM — ключевые путешествия

### CJM A. Воскресное планирование (вместе, 15–25 мин)

```
Триггер: заканчивается еда / хотим спокойную неделю
  → Открыть «План недели»
  → Увидеть авточерновик (ИИ/алгоритм по правилам + запасам + разнообразию)
  → Жена: дизлайк 1–2 блюд, замена в 1 тап
  → Данила: проверить бюджет недели и мясо
  → «Собрать корзину» → разбивка Ашан / Парное / Пятёрочка
  → Экспорт: список / шаринг в мессенджер / печать
  → Эмоция: спокойствие, «неделя закрыта»
```

**Боли на пути:** слишком много выбора; спор; непонятные цены.  
**Фичи-щиты:** авточерновик, лимит замен, «почему предложили», бюджет-бар.

### CJM B. «Что из холодильника» (будни, 2–5 мин)

```
Триггер: 18:40, устали, продукты «есть что-то»
  → Кухонный режим → «Из запасов»
  → Быстрый ввод: пресеты (курица, яйца, картошка…) + слайдеры количества
  → Топ-5 блюд с % покрытия и «чего не хватает на 50 ₽»
  → Выбор → рецепт крупно → старт таймера
  → Отметить «съели / осталось»
```

### CJM C. Большая готовка (1 час)

```
Триггер: дежурный день
  → Экран «Сегодня готовим партию»
  → Порядок: бульон → духовка → крупа → заготовки
  → Таймеры параллельно
  → Фасовка: «на сколько дней хватит» + наклейки/подсказки в UI
  → Остатки автоматически попадают в инвентарь
```

### CJM D. Закупка мяса в Молоково (раз в 2–4 недели)

```
Триггер: календарь закупки / низкий запас белка
  → Режим «Рейд в Парное мясо»
  → Список кг по позициям + бюджет поездки
  → Чеклист в телефоне на прилавке
  → По возвращении: «оприходовать» в морозилку (1 кнопка по позициям)
```

### CJM E. Контроль месяца (Данила, 5 мин раз в неделю)

```
Триггер: воскресенье вечер / после закупки
  → Бюджет: готовка / вино / джин / вкусняшки / факт
  → Отклонения: «сыр и фуэт +900 к плану»
  → Коррекция следующей недели (больше дешёвых batch / меньше рыбы премиум)
```

### CJM F. Срыв плана (без вины)

```
Триггер: лень / гости / болезнь ребёнка
  → «План сломался»
  → Варианты: перенос batch, упрощённый ужин <20 мин, заморозка слота
  → Лог срыва (опционально) только для статистики экономии, не для стыда
```

## 6. Информационная архитектура (IA)

### 6.1. Верхний уровень навигации

| Раздел | Для кого | Суть |
|--------|----------|------|
| **Сегодня** | Жена / дежурный | Меню дня, шаги, таймеры, замена |
| **План** | Оба | Календарь 7/14/90 дней, batch-лента |
| **Запасы** | Оба | Инвентарь + подбор блюд |
| **Корзина** | Закупщик | Списки по магазинам, порции, дни |
| **Рецепты** | Оба | Каталог, избранное, фильтры |
| **Бюджет** | Данила (+ прозрачно жене) | Прогноз/факт, корзины «еда/алко/вкусняшки» |
| **Семья** | Оба | Профили, запреты ребёнка, предпочтения, магазины |

На мобильном по умолчанию открывается **Сегодня** (профиль «Кухня»).  
На десктопе / для Данилы — **План + Бюджет**.

### 6.2. Сущности домена

```
Product          — продукт (единица хранения, магазин, цена, срок, зона: холодильник/морозилка/шкаф)
InventoryLot     — партия запаса (кол-во, дата, срок годности)
Recipe           — рецепт (ингредиенты, шаги, batchDays, теги, детская адаптация)
RecipeVariant    — вариант (для ребёнка / без острого / из остатков)
MealSlot         — слот плана (дата, приём пищи, recipeId, порции, статус)
Plan             — набор слотов (неделя / произвольный период)
Basket           — корзина закупки
BasketLine       — строка (продукт, кол-во, магазин, покрыто запасом?, источник: рецепты)
BudgetLedger     — статьи бюджета и факты
PreferenceRule   — правила (не чаще курицы N раз/нед, рыба 2 раза, печень ок…)
CookSession      — факт готовки (что сварили, выход порций, остаток)
```

## 7. Ядро продукта — модули (подробно)

### M1. Каталог рецептов (глубокий)

**Обязательные поля рецепта**

- Название, тип (завтрак / суп / основное / гарнир / перекус / соус / заготовка)
- Время активное / пассивное; сложность 1–3
- Batch: на сколько дней; хранение (холодильник/морозилка); разогрев
- Порции baseline + масштабирование
- Ингредиенты: продукт, брутто/нетто, можно заменить на…
- Шаги: короткие, нумерованные, с пометками «пока это тушится → сделай X»
- Оборудование: духовка / мультиварка / аэрогриль / плита
- Теги: мясо/птица/рыба/печень/веге, кухня, «<20 мин», «из фарша»
- **Детский блок:** что убрать, чем заменить, текстура (пюре / мягкие куски)
- Стоимость партии (по прайсу) и на порцию
- «Почему в ротации»: закрывает белок / овощи / дешёвый день

**UX рецепта**

- Режим «Кухня»: только шаги + ингредиенты крупно + keep-screen-on
- Режим «Планирование»: цена, batch, теги, совместимость с запасами
- Кнопки: в план / в корзину / приготовить из запасов / заменить

### M2. Умный подбор из запасов (ключевой алгоритм)

**Вход**

- Инвентарь (кол-ва)
- Опционально: приём пищи, время, кто ест (с ребёнком / только взрослые), max сложности
- Предпочтения и история (не повторять блюдо N дней)

**Выход**

Ранжированный список рецептов:

| Поле | Смысл |
|------|--------|
| `coverage` | % ингредиентов, которые уже есть (по массе ключевых) |
| `missing` | чего не хватает + оценка ₽ |
| `portionsPossible` | порций по самому узкому ингредиенту |
| `wasteScore` | насколько блюдо «съедает» скоропорт |
| `effort` | время |
| `childOk` | совместимость с правилами дочки |
| `why` | 1 строка объяснения |

**Логика скоринга (v1, детерминированная, без LLM)**

```
score =
  + 40 * coverage
  + 20 * normalize(portionsPossible)
  + 15 * wasteScore          # приоритет продуктов near expiry
  + 10 * preferenceFit       # любимое мясо/теги
  + 10 * varietyBonus        # давно не было
  - 15 * missingCostNorm     # штраф за докупку
  - 10 * effortNorm
  - ∞ если hard-constraint нарушен (орехи ребёнку, запрещённый субпродукт)
```

**Режимы подбора**

1. **Строгий** — только то, чего хватает полностью  
2. **Почти** — нехватка ≤ X ₽ или ≤ 2 позиций  
3. **Спасение скоропорта** — сортировка по expiry  
4. **Только детское** / **семейное общее**

**Позже (v2):** LLM-ранжирование формулировок и «креативные сборки остатков», но **математика покрытия всегда считается кодом**, не моделью.

### M3. Планировщик меню (календарь + batch)

- Горизонты: сегодня / 7 / 14 / 90 дней  
- Автогенерация с constraints:
  - бюджет недели
  - частота мяса/рыбы/птицы/печени
  - без повтора *одного и того же блюда* в горизонте (гарниры могут циклиться осознанно)
  - batch-совместимость (суп на 3 дня подряд — норма)
  - нагрузка на готовку: не два «сложных» дня подряд
- Ручные замены с сохранением бюджета (±допуск)
- Шаблоны: «Эконом», «Больше мяса», «Рыбная неделя», «Жара/мультиварка»
- Визуальная batch-лента: цветом показано, что разогрев, а что новая варка

### M4. Корзина закупок (от рецептов → магазины)

**Вход:** выбранные рецепты + порции + на сколько дней / слоты плана  
**Процесс:**

1. Суммировать ингредиенты с масштабом порций  
2. Вычесть инвентарь (с учётом резерва «не трогать» — напр. неприкосновенный запас гречки)  
3. Округлить до упаковок (1 кг фарша, бутылка масла) — **правила фасовки**  
4. Разложить по магазинам (дефолт продукта + ручной оверрайд)  
5. Показать ₽ по магазинам и итог  
6. Отметить «куплено» / «перенесено»

**Фичи корзины**

- Вкладки: Парное мясо / Ашан / Пятёрочка / Прочее  
- Режим «Рейд в Молоково» (только белок)  
- Режим «Добор Пятёрочка» (вкусняшки отдельным списком, не смешивать с базой)  
- Экспорт: текст в Telegram/WhatsApp, checklist print, копирование  
- «Умное округление»: объяснить «берём 1 кг, хотя надо 700 г — остаток уйдёт в котлеты»  
- Сравнение: корзина A (эконом) vs B (как в плане)  

### M5. Инвентарь / запасы

- Зоны: холодильник, морозилка, шкаф, «открыто»  
- Быстрый ввод: чипы продуктов, голос позже, сканер штрихкода позже  
- Срок годности и предупреждения за 1–2 дня  
- Автосписание при «приготовил» (по рецепту) + ручная корректировка «съели меньше»  
- Морозилка: слоты «фарш 0.5», «бульон», «суп порция»  
- Инвентаризация раз в неделю: мастер «пройтись за 5 минут»

### M6. Бюджет и деньги

Три контура (как в брифе):

1. **Базовая готовка**  
2. **Алкоголь** (джин+тоник+лимон / вино)  
3. **Вкусняшки** (фуэт, сыры, чипсы…)

Фичи:

- План месяца / факт (ручной ввод чека или сумма закупки)  
- Прогноз «если доесть текущий план»  
- Алерт: «вкусняшки уже 70% недельного лимита»  
- Не морализировать алкоголь — просто учитывать  
- Цель: полная картина 50–80к без сюрпризов

### M7. Семейные правила и предпочтения

- Чёрный список / серый список продуктов и блюд  
- Частотные caps (курица ≤ N, печень ≤ M)  
- Детский профиль ограничений (жёсткий)  
- «Любимое жены» / «любимое Данилы» с бустом в скоринге  
- История дизлайков → не предлагать N недель

### M8. Кухонный режим исполнения

- Чеклист шагов + таймеры (несколько параллельно)  
- «Режим мокрых рук»: огромные тапы, без тонких жестов  
- Keep awake  
- Голосовые подсказки — фаза 2  
- После готовки: «сколько порций вышло?» → инвентарь

### M9. Аналитика и инсайты (без дашборд-ада)

Примеры инсайтов, не графиков ради графиков:

## 9. UX-принципы (чтобы «как ни крути — удобно»)

1. **Два лица одного приложения** — Кухня / Командный центр, одни данные.  
2. **Сначала действие, потом настройка.**  
3. **Любой автоплан можно сломать за 1 тап** — доверие важнее идеальности.  
4. **Объясняй «почему»** у автоподбора (1 строка).  
5. **Деньги всегда рядом с едой**, но не кричат.  
6. **Ребёнок — правила, не отдельное приложение.**  
7. **Офлайн-first** на HTML-этапе: всё работает без интернета после загрузки.  
8. **Пустые состояния с действием** («запасы пусты → 5 чипов частого» ).  
9. **Безопасные дефолты** под вашу семью уже вшиты (печень ок, орехи ребёнку нет…).  
10. **Честность > стыд** про алкоголь и чипсы.

### Критерии удобства для жены (acceptance)

- С телефона одной рукой  
- «Сегодня» читается с 1 метра  
- Замена блюда ≤ 2 тапа  
- Рецепт не требует скроллить рекламу/воду  
- Не нужно понимать бюджет, чтобы приготовить

### Критерии удобства для Данилы (acceptance)

- Виден прогноз месяца и недельный ₽  
- Корзина по магазинам экспортируется  
- Правила частоты мяса/рыбы настраиваются  
- Инвентарь и план консистентны  
- Можно обслужить систему за 15 мин в неделю

## 10. Алгоритмы и политики (спеки для разработки)

### 10.1. Масштабирование порций

```
scale = targetServings / recipe.baseServings
ingredient.qty = round(recipe.qty * scale, rule)
```

Правила округления по типу продукта: яйца — целые шт; специи — мин. порог; мясо — до 50 г.

### 10.2. Сборка корзины

```
need = sum(scaled ingredients across selected meal slots)
buy = need - inventory + reservedBuffer
buy = applyPackRounding(buy)
group by defaultStore
price = buy * unitPrice
```

### 10.3. Генерация плана на N дней

1. Расставить batch-якоря (супы на 3 дня, тушёное на 2–3)  
2. Закрыть белковые квоты недели  
3. Заполнить завтраки из пула с anti-repeat  
4. Детские перекусы — отдельно, дёшево, без сахара  
5. Прогнать бюджет; если > лимита — заменить самые дорогие слоты на эконом-эквиваленты  
6. Выдать plan + expectedBasket + confidence

### 10.4. Конфликт предпочтений

Если жена дизлайкнула блюдо:

- убрать из слота  
- предложить 3 замены того же типа/цены/batch  
- запомнить вес дизлайка

## 11. Техническая архитектура (эволюция)

### Фаза A — HTML Local-First (сейчас → прод-MVP)

```
index.html
app/           # модули UI
data/          # recipes, products, prices, rules (JSON)
state/         # localStorage / IndexedDB
```

- Один входной HTML или крошечный бандл без обязательного сервера  
- Состояние: план, запасы, корзина, бюджет, предпочтения — в **IndexedDB**  
- Импорт/экспорт JSON-бэкапа (файл) — критично  
- Service Worker опционально (PWA offline)

**Плюсы:** быстро, приватно, работает в деревне при слабом интернете.  
**Минусы:** нет синка между двумя телефонами без ручного экспорта.

### Фаза B — Sync Light (когда станет больно жить без синка)

- Простой backend (Auth + DB + sync)  
- Семейный аккаунт на 2 устройства  
- Конфликт-резолюшн: last-write-wins по сущностям + «запасы» осторожнее  
- Сервер не обязателен для расчётов — расчёты на клиенте

### Фаза C — Умный слой

- Опциональный AI-assist для замен и текста шагов  
- Распознавание чеков  
- Никогда не отдавать AI единоличный контроль над бюджетом/покрытием запасов

### Принципы данных

- Цены версионируются (`priceUpdatedAt`)  
- Рецепты отделены от плана  
- Все деньги считаются в одном money-модуле  
- Правила ребёнка — hard constraints в одном policy-модуле
